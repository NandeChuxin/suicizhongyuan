# 碎瓷重圆 · 数字文化传承体验

> 景德镇传统手工制瓷技艺 · 民间修补文化 · 器物生命史 —— Web 端互动叙事作品
> 核心表达：修复一件瓷器，接续一段生活，让一门手艺被更多人记住。

## 作品定位

《碎瓷重圆》是一套以景德镇传统手工制瓷技艺、民间修补文化与器物生命史为核心的数字叙事体验。作品通过器物档案、纹样辨识、碎片拼合、锔瓷体验、传承资料摘记与虚拟窑址考察，让参与者从一件瓷器看见一群人的劳动、一座城市的记忆和一门手艺的当代传承。

内容分层全站统一为五种标签：**史实依据 / 民间传说 / 原创叙事 / 数字示意 / 待人工核实**。
器物、人物与经历为原创设定（原创叙事），工艺与贸易语境依公开资料整理（史实依据），
民间传说明确标注叙事性质，所有交互均为数字示意。不使用"真实故事""真实还原"等称谓。

## 主流程（九屏）

启程 → 档案柜 → 委托 → 拼合 → 记忆 → 修复抉择 → 证书 → 考察（写实 3D）→ 展厅

- 六件数字器物（8/10/12 片碎片），各配 8 段第一人称编年记忆，共 48 段；
- 拼合时每归位一片只推进页面底部的修复进度条（整体完成度实时更新）；
  全部瓷片归位后，才统一展开翻页式「器物长卷」，逐页阅读这 8 段记忆；
- 修复方式四选一：隐痕修复 / 金线表达 / 现状保存（隐藏）/ 锔瓷体验；
- 修满 2 / 4 / 6 件依次开放御窑厂、古窑、陶溪川三处写实 3D 考察点；
- 证书页提供修复证书下载、分享卡、文化展签与「我读懂的器物档案」；
- 每件器物在 `src/data/vessels.js` 挂统一文化档案字段：
  `culturalContext / craftRoles / referenceScope / contentLayers / sources / digitalTranslation / uncertainty`；
- 数字展厅无需进度即可浏览六件器物 3D 与展签，不写入存档；
- 全流程可随时召唤「窑火问答」数字讲解员（见下节），展厅浏览同样不写入主线进度。

## 数字讲解（窑火问答）

九屏中的任意节点都能召唤一套统一的讲解体验：本地知识问答 + 原创古人数字角色 + AI 合成语音 + 字幕。

- **知识边界**：讲解智能体只回答六件器物档案、景德镇制瓷工序、器型/纹样/胎釉、
  锔瓷/金缮/现状保存、民间修补文化、御窑厂/古窑/陶溪川考察与本项目已解锁记忆；
  资料不足时统一回答「现有展览资料中没有足够依据回答这个问题…」，不以肯定语气补全未知内容；
- **五层标签**：每条回答都带 `史实依据 / 民间传说 / 原创叙事 / 数字示意 / 待人工核实` 标签，并可展开「查看资料来源」；
- **原创角色**：默认讲解员「画坯匠 · 阿墨」为**依据时代制瓷工种创作的数字角色，不是真实历史人物复原**，
  首次出现前均展示该声明；涉及现代研究、来源与不确定性时改由中性的「数字策展员」作答；
- **语音合规**：标注「AI 合成角色语音」，不克隆或仿制任何真实人物声音，不训练未授权录音；
  字幕与声音同源，无语音服务时自动回退为字幕 + 浏览器通用语音；
- **边界**：智能体不替用户拼图、不改答案、不跳关、不改存档；展厅问答不写入 `porcelain-reunion-progress-v1`。

远程大模型接入为**可替换适配层**（默认关闭，走本地检索）：配置 `VITE_GUIDE_ENDPOINT`
指向自建后端即可启用。前端不保存任何密钥，只发送最少必要上下文（页面/器物/热点/修复方式），
不发送昵称、存档等个人数据；带超时、失败回退，并在展示前做领域与标签校验。

## 文化资料边界

- 六件器物的馆藏原型参考图来自故宫博物院官网公开藏品资料，出处见
  `public/patterns/real/ATTRIBUTION.md`，**仅限非商业教育演示**；
- 线上公开版设 `VITE_ONLINE_MODE=1`：停用馆藏照片，只保留文字出处（见 `docs/部署说明.md`）；
- 传承资料摘记（`src/data/quotes.js`）全部为**待核实的草稿概括**，页面称
  「传承资料摘记 · 待核实」；不得冒充逐字引述或已完成的传承人采访；
- 素材与表述性质详见 `docs/素材与内容来源.md`；
- 不引入外部商用图库、老照片或 AI 生成图片；新增视觉一律 Canvas/SVG 程序化生成。

## 访问方式与部署

本作品是**纯网页应用**：无需下载、无需安装任何客户端或运行时，打开浏览器访问网址即可使用。

### 在线访问（面向观众）

部署完成后，访问 `https://<你的域名>/`（或托管平台的默认域名）；放在子目录时访问
`https://<你的域名>/porcelain/`。页面使用 hash 路由，静态托管无需额外重写规则。

### 构建与发布（面向维护者）

```powershell
npm ci                 # 安装依赖（仅开发/构建需要）
npm test               # Node 单元测试
npm run build          # 产出 dist/ 静态网站（相对路径，可放任意子目录）
npm run models         # 由根目录中文名高模生成 public/models/ 网页副本
```

把 `dist/` 整个目录上传到任意静态托管（Nginx / Apache / GitHub Pages / Vercel / Netlify /
对象存储）即可。`dist/models/` 含 `hero.glb` 与 `vessels/*.glb`，必须一并上传；
缺少时页面会静默回退程序化器身。公网发布建议加 `VITE_ONLINE_MODE=1` 构建线上版
（隐藏馆藏照片，只保留文字出处）：

```powershell
$env:VITE_ONLINE_MODE = "1"; npm run build; Remove-Item Env:VITE_ONLINE_MODE
```

本地自查可用 `npm run preview`（或 `node serve.cjs`，端口取 `PORT`），确认无误后再上传；
具体托管步骤与检查清单见 [`docs/部署说明.md`](docs/部署说明.md)。服务端只需正确返回静态文件，
`.glb` 建议使用 `model/gltf-binary` MIME；首次打开需要联网加载页面与模型，不依赖 Service Worker 或离线缓存。

## 玩法

1. 启程页可先「十秒读懂」作品要保护什么、由谁传承、你能理解什么；
2. 接受委托，阅读器物设定与原型参考卡，输入 20 字以内修复师昵称；
3. 拖动瓷片到器身轮廓，Q / E 或右键旋转，让纹路与「对花」投影重合后吸附；
4. 每归位一片，页面底部的修复进度条实时推进；双击已归位碎片可查看纹样观察线索；
5. 全部归位后自动展开翻页式「器物长卷」（长故事，可逐页翻读），读毕进入修复抉择：
   隐痕修复 / 金线表达 / 锔瓷体验，或选择现状保存（隐藏）；
6. 证书页可下载修复证书、生成分享卡、打开文化展签与「我读懂的器物档案」；
7. 修满 2/4/6 件解锁三处写实考察点；六件全修走遍三处触发终局成就。

## 验收

- `npm test`：六件器物参数、GLB 映射、原型参考卡、碎片管线、记忆字数等结构校验；
- `tests/immersive-e2e.html`：浏览器端到端自测（拼合→证书→三站考察→终局成就）；
- `node scripts/verify-porcelain-grade.mjs`：瓷器亮度/高光分级回归（启程页原亮度，其余页面收敛，需先起开发服务器）；
- `node scripts/verify-typography.mjs`：字号放大后的排版体检（横向/纵向溢出、文字裁切、文字块重叠，需先起开发服务器）；
- 改动 `src/data/vessels.js` 后必须跑 `npm test`（有字数与结构校验）；
- 本轮改进的逐项验收记录见 `docs/改进验收.md`；
- 「沉浸式数字博物馆与 AI 古人讲解」升级的逐项验收见 `docs/数字博物馆导览验收.md`。
