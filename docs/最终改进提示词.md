# 《碎瓷重圆》参赛前最终改进提示词

你是《碎瓷重圆》项目的开发工程师和内容校对负责人。这是一个使用 Three.js、Vite 和原生 JavaScript 制作的 Web 端陶瓷文化互动作品，准备参加“民族文化创新表达”作品赛项。

本轮工作的目标不是继续增加功能，而是把现有作品从“青花瓷修复互动”提升为“以景德镇传统手工制瓷技艺、民间修补文化和器物生命史为核心的数字文化传承体验”。请先完整阅读本提示词、项目现有代码及资料文档，再开始修改。

## 一、作品最终定位

统一使用以下定位：

> 《碎瓷重圆》是一套以景德镇传统手工制瓷技艺、民间修补文化与器物生命史为核心的数字叙事体验。作品通过器物档案、纹样辨识、碎片拼合、锔瓷体验、匠人资料与虚拟窑址考察，让参与者从一件瓷器看见一群人的劳动、一座城市的记忆和一门手艺的当代传承。

作品核心表达为：

> 修复一件瓷器，接续一段生活，让一门手艺被更多人记住。

内容必须始终围绕以下六个关键词：景德镇传统手工制瓷技艺、活态传承、器物生命史、惜物与修补文化、数字档案、互动叙事。

不得为了制造“民族感”而添加脱离语境的民族服饰、图腾、纹样或装饰符号。不得把原创人物、虚构器物经历或程序化视觉素材表述为真实史料、真实馆藏记录或真实传承人口述。

## 二、项目现状与工作边界

主流程入口为 `index.html`，主控逻辑为 `src/immersive.js`，样式为 `src/immersive.css`。器物数据在 `src/data/vessels.js`，文化内容在 `src/data/culture.js`，引述草稿在 `src/data/quotes.js`，考察模块在 `src/kaocha/`。

以下功能已经存在，本轮不得重复开发或推翻：

- 六件器物修复主线与 2/4/6 件解锁进度；
- 3D 器物、碎片拼合、旋转与吸附判定；
- 中国锔瓷、金线表达、隐痕修复和现状保存；
- 御窑厂、古窑、陶溪川三处 3D 考察点；
- 分享卡、二维码浮层、数字展厅；
- 《瓷器记忆手记》和文创视觉样张；
- 窑火数据示意卡、点击吸附模式、字号与 aria-live；
- `VITE_ONLINE_MODE=1` 线上授权边界；
- GLB 加载失败后的程序化器身回退。

不得改动吸附判定常量、碎片 XY 平面约束、存档 key `porcelain-reunion-progress-v1`、器物解锁门槛和现有主流程手感。不得引入外部商用图库、老照片或 AI 生成图片。新增视觉只能复用已有资产或通过 Canvas/SVG 程序化生成。

## 三、P0：文化资料与口径统一

### 任务 1：建立统一文化档案结构

为 `src/data/vessels.js` 中每件器物补充或整理统一的文化档案字段，字段至少包括：

- `culturalContext`：制作、使用、流通或修补语境；
- `craftRoles`：相关工种，例如拉坯、利坯、画坯、施釉、烧窑、锔补；
- `referenceScope`：数字器物具体参考了馆藏原型的器型、纹样、釉色或工艺中的哪些部分；
- `contentLayers`：分别列出史实、民间传说和原创叙事；
- `sources`：来源名称、机构、URL、访问日期和用途；
- `digitalTranslation`：该文化内容被转化成了什么数字交互；
- `uncertainty`：图测、推测、缺失资料或待人工核实内容。

字段命名可根据现有数据结构做小幅调整，但六件器物必须结构一致。页面不得一次性堆出全部字段，应在现有原型参考卡、文化展签或知识抽屉中分层展示。

### 任务 2：全面清理资料矛盾

以 `src/data/vessels.js` 当前器物数据为唯一事实入口，检查并统一以下位置：

- `README.md`；
- `交接说明.md`；
- `docs/素材与内容来源.md`；
- `public/patterns/real/ATTRIBUTION.md`；
- `src/data/culture.js`；
- `src/data/quotes.js`；
- 首页初始占位文案、档案柜、委托页、展厅、证书和电子手记；
- 所有档案编号、年代、器物名称、原型编号和纹理用途说明。

重点修复已知问题：

- 清除“清雍正 1725”和当前“明嘉靖”之间的旧口径冲突（注意：现行数据为“嘉靖二年 · 1523”，见 vessels.js 梅瓶记忆 mp-01；“1524”是档案号 QH-1524 的一部分，不是年份，不得据此改动年份）；
- 清除首页旧档案编号占位；
- 更新馆藏照片用途说明：三维环绕器身采用程序化纹样时，不得继续声称使用馆藏照片作为三维器身纹理；
- 核查“元代创烧”“十窑九不成”“落选即碎”等表述，将其标记为有来源的史实、俗语/传说或创作示意；
- 删除无法找到可靠来源的绝对化断言，或明确标记为 `[待人工核实]`。

不要凭模型记忆补写史实。找不到可靠依据时，保留谨慎表达和待核实标记。

### 任务 3：规范文化内容分层

在用户可见页面形成统一标签体系：

- `史实依据`：有可追溯机构、书目或正式资料支持；
- `民间传说`：说明其叙事性质，不解释为科学事实；
- `原创叙事`：项目为建立情感连接而创作；
- `数字示意`：为交互和可视化进行的简化表达；
- `待人工核实`：尚未完成出处核对，不可作为正式引述。

所有页面统一使用上述称谓，不再混用“真实故事”“真实还原”等容易引起误解的表达。

## 四、P0：文化主体与传承之声

### 任务 4：重构引述草稿的数据结构和页面称谓

完善 `src/data/quotes.js`，每条记录增加：

- `speaker`：作者、机构或受访者；
- `speakerRole`：与制瓷、研究或地方文化的关系；
- `sourceType`：官网、出版物、纪录片或访谈；
- `sourceTitle`；
- `url` 或出版信息；
- `accessedAt`；
- `quoteType`：逐字引述或资料概括；
- `authorization`：公开资料、已授权、待授权或不适用；
- `pending`。

在所有 `pending: true` 的内容仍未人工核实前，将页面中的“真实传承之声”改为“传承资料摘记 · 待核实”。不得用引号伪装成逐字引述；资料概括必须明确写成“根据相关资料概括”。

同时新增 `docs/传承人资料采集模板.md`，包含：姓名或匿名身份、职业/工种、采访日期、地点、采访者、原始文件路径、公开授权范围、允许使用姓名/声音/影像的选项、原话、页面节选、人工核实人和核实日期。

本轮不得虚构传承人姓名、经历、采访和授权。真实采访与最终授权由人工完成，代码只提供结构、占位和清晰标记。

### 任务 5：强化“人—技艺—城市”关系

保留现有六位原创委托人，但在界面中明确：

- 真实资料负责解释文化；
- 原创人物负责建立情感；
- 用户操作负责形成体验。

为六件器物分别确定一个清晰的文化主题：

1. 花鸟纹梅瓶：纹样、绘制与日常使用；
2. 玉壶春瓶：官窑制度、检验与考古记录；
3. 云龙纹罐：瓷器贸易与文化交流；
4. 釉里红高足杯：窑火控制、失败与匠人经验；
5. 祭红釉蒜头瓶：民间传说与工艺事实的区分；
6. 玲珑瓷碗：分工、师徒学习与当代传承。

在档案柜或展签上呈现这些主题，让六件器物构成一套文化学习路径，而不只是六关游戏。

## 五、P1：首页与主流程表达调整

### 任务 6：首页十秒文化说明

在不破坏当前首页构图和交互动线的前提下，加入一段简短文化引导。推荐文案：

> 一件瓷器，经过泥、火、笔与人的双手。  
> 当它破碎，我们修复的不只是形状，也在重新阅读它背后的技艺、生活与记忆。

首页应在十秒内回答：保护什么、由谁传承、用户能理解什么。不得增加大段百科文字，可使用一个短引导、四张轻量信息卡或可展开说明。

推荐四个内容节点：

1. 一片瓷：材料、器型与纹样；
2. 一群人：画坯、烧窑、修补与使用者；
3. 一座城：景德镇的生产、生活和交流；
4. 一次选择：数字时代如何记录、修复和传播。

### 任务 7：让交互结果体现文化学习

复用现有证书和文化展签，在修复完成后生成“我读懂的器物档案”，至少记录：

- 用户修复的器物；
- 识别过的纹样或器型线索；
- 对应工艺或文化主题；
- 用户选择的修复方式及其伦理含义；
- 史实/原创/数字示意说明；
- 资料来源入口。

优先复用现有数据和导出逻辑，不再新建一套独立进度系统。

## 七、工程与内容验收标准

完成修改后必须执行并通过：

```bash
npm test
npm run build
```

同时检查：

1. 不改变吸附判定、XY 拖拽、localStorage key 和 2/4/6 解锁链；
2. 不增加外部图片、AI 图片和无授权素材；
3. 所有史实、传说、原创、数字示意和待核实内容分层明确；
4. 不伪造引述、采访、授权、机构背书或统计数据；
5. 六件器物的名称、年代、档案号、馆藏原型和页面展示一致；
6. 普通构建与线上模式构建均可用；
7. Chrome 桌面端和 375px 宽度均可操作；

9. 将完成情况写入 `docs/改进验收.md`，不得只在聊天中报告。

## 八、明确不做

本轮禁止扩展以下内容：

- 新增第七件器物或更多关卡；
- 新增更多 3D 景区；
- 增加物理引擎或改变碎片操作手感；
- 新增与文化学习无关的小游戏；
- 编造新的历史故事来填补资料空白；
- 用民族服饰、图腾或纹样拼贴制造表面上的“民族性”；
- 执行真实线上部署；
- 生成正式二维码；
- 代替人工完成传承人口述核实与授权；
- 改写或更新 `docs/3分钟演示脚本.md` 等参赛演示材料（人工负责，本轮不做）。

执行顺序固定为：先核对数据与资料，再修改数据结构，然后调整用户可见文案与页面，最后补文档并完成构建、测试和响应式验收。发现资料冲突时，优先保留原始证据和待核实标记，不得自行猜测。
