## 1. 影片定位与叙事策略

### 1.1 评审要回答的四个问题

1. **做了什么**：一个以景德镇青花瓷修复为题的 Web 互动叙事作品，不是单点 Demo。
2. **怎么玩**：拼合碎瓷 → 读器物长卷 → 选择修复方式 → 完成工序 → 得到证书 → 走进三处写实考察 → 回到展厅与终局。
3. **难在哪**：碎片与纹样同源、全息拼合空间、四种修复的差异化收尾、写实 3D 的考据与性能预算、AI 讲解的内容边界。
4. **态度是什么**：修复不是把裂痕抹掉；有些破碎本身就是证据。技术服务于这个判断。

### 1.2 一条主线：跟随一件梅瓶

主片只完整修一件器物——**青花花鸟纹梅瓶（明嘉靖，8 片，QH-1524）**。

- 它的碎片数最少，适合在 110 秒内完整展示拼合；
- 它的八段记忆从嘉靖二年写到今天，时间跨度最长，适合承载"器物生命史"；
- 它的纹样是花鸟，便于在特写里看清"断开的笔画重新接上"。

其余五件器物、四处修复结果、三处考察点、六器展厅，用"能力证明"的方式穿插，不打断主线。

### 1.3 三个评审锚点（旁白中要出现）

- **完整可玩**：九屏不是幻灯片，每一步都有真实交互与状态。
- **技术同源**：碎片不是贴纸，纹样不是手绘冒充，证书不是模板合成。
- **文化诚实**：五层标签、原型出处、置信度分级、AI 未知回答。

### 1.4 叙述口径（必须遵守）

| 不说 | 改说 |
|---|---|
| 真实还原 / 1:1 复原 / 考古级复原 | 数字示意 / 原型参考 / 数字推演 |
| 真实故事 / 真实传承人采访 | 原创叙事 / 传承资料摘记（区分逐字与概括） |
| AI 复原的古人讲解员 | 原创数字角色「器灵 · 阿圆」 |
| 六件全部在本片内修完 | 主片完整修一件；其余用预置存档展示后期状态（片尾标注） |
| 修复结果有标准答案 | 四种方式对应四种修复伦理，没有标准答案 |

## 2. 成片规格与交付物

### 2.1 画面

- 录制：OBS 窗口捕获，1920×1080，60fps，CQP 18，关键帧 2s，NVENC H.264。
- 若器身在 1920×1080 中偏小：改用 1600×900 录制，后期 1.2× 放大到 1080p，加 8% 轻锐化；不要用浏览器缩放改变布局。
- 色彩：sRGB / Rec.709；不要拍 HDR；暗部保留细节，金色高光不裁切。
- 帧率：60fps 录制，30fps 时间线；慢动作按 50% 解释，不用光流补帧（UI 文字会糊）。

### 2.2 声音

- 旁白单独录制：48kHz / 24bit，-18 LUFS，峰值 -12 dBFS；不要与鼠标、键盘同录。
- 系统声：单独一轨，保留瓷鸣、叩声、翻页声、转场声；旁白下压 -6 至 -9 dB。
- 音乐：只用可商用/已授权的低频氛围垫，或完全用项目自身的程序声景铺底；不要用强旋律，避免与旁白抢注意力。
- 关键声音点：归位瓷鸣、叩瓷三态、翻页、上釉完成、成就和弦。

### 2.3 字幕

- 字体：思源宋体 CN Medium；字号 24px（1080p）；行距 1.25；每行 ≤ 18 字，最多 2 行。
- 颜色：暖白 `#F5F2EA`；关键词用金色 `#C9A961`；不要用纯白。
- 底衬：黑色 55% 圆角条，或轻微投影；不要用大面积色块。
- 安全区：距底 96px；拼合屏底部有进度条，字幕上移到 200px；证书屏字幕放左上，避开右侧按钮列。
- 旁白与字幕同源：字幕就是旁白稿，不改写、不增删信息。

## 3. 录制前准备

### 3.1 环境清单

- [ ] 显示器 1920×1080，系统缩放 100%；浏览器缩放 100%。
- [ ] Chrome 或 Edge，开启硬件加速；关闭所有扩展；只保留一个标签页。
- [ ] 隐藏书签栏（Ctrl+Shift+B）；关闭下载气泡、通知、系统更新提示。
- [ ] 深色桌面背景；窗口捕获而不是全屏捕获，避免桌面图标入镜。
- [ ] 鼠标指针：Windows 指针大小 2，白色带黑边；关闭"打字时隐藏指针"。
- [ ] 电源计划：高性能；关闭录屏期间的杀毒扫描与网盘同步。
- [ ] 运行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173/`，确认控制台无报错。
- [ ] 首次进入每件器物、每处考察点、展厅六器，等待 GLB 加载完成，完成预热。

### 3.2 三个存档槽（关键）

| 槽位 | 状态 | 用途 |
|---|---|---|
| 槽 1 | 0/6，未修复 | 启程、档案柜、委托、完整拼合、长卷、抉择、证书 |
| 槽 2 | 2/6，第一件已完成 | 御窑厂已解锁；考察页、证书复访 |
| 槽 3 | 6/6，三站已走遍 | 六器展厅、终局成就、全器物展示 |

准备方式：

1. 槽 1 清空后正常游玩到 0/6；
2. 槽 2 由槽 1 正常游玩导出 JSON 后导入，或直接玩到 2/6；
3. 槽 3 用正常游玩/导入的 6/6 存档，**不要手改 localStorage**；
4. 三个槽统一署名「沈砚」，证书日期一致，便于剪辑时匹配；
5. 导出存档时勾选"包含修复师昵称"，但片中不展示任何个人数据。

> 预置存档只用于展示后期状态，不用于伪造"本片内完成六件"。片尾字幕注明："终局与六器展厅使用已完成存档演示"。

### 3.3 预热与素材

- 六件器物：依次进入委托页，等待模型加载完成，再返回；确保 HTTP 缓存命中。
- 三处考察点：依次进入御窑厂、古窑、陶溪川，等待场景构建完成。
- 展厅：六件逐一切换，等待 GLB 接管。
- 讲解：打开一次窑火问答，播放一条回答，确认语音/字幕可用。
- 证书：先下载一次，确认下载目录与文件名；关闭"每次询问保存位置"。

### 3.4 录制参数（OBS）

| 项 | 设置 |
|---|---|
| 来源 | 窗口捕获（浏览器），或显示器捕获 + 干净桌面 |
| 分辨率 | 1920×1080（或 1600×900 后 1.2× 放大） |
| 帧率 | 60fps |
| 编码 | NVENC H.264，CQP 18，preset Quality，关键帧 2s |
| 音频 | 48kHz，桌面音频 1 轨，麦克风 1 轨（若同录） |
| 轨道 | 1 系统声，2 旁白，3 预留 |
| 监听 | 关闭麦克风监听，避免回声 |

### 3.5 拍摄顺序（按状态分组，不是成片顺序）

1. **槽 3**：展厅六器、自动导览、终局成就、三站空镜。
2. **槽 2**：御窑厂考察、证书复访、档案卡。
3. **槽 1**：启程、档案柜、委托、完整拼合、长卷、抉择、金线工序、证书。
4. **B-roll**：锔瓷四钉、现状保存、隐痕证书、模型加载条、降画质提示、手机端倾斜、分享二维码。
5. **系统镜头**：存档面板、导出/导入、键盘焦点、字号。

> 先拍"高状态"再拍"低状态"，避免反复清档；B-roll 单独拍，剪辑时插入，不在一条时间线里连续操作。

### 3.6 试录与场记

- 试录 15 秒：检查画面是否被裁、颜色是否偏、声音是否同步、GLB 是否已加载。
- 每条镜头前用手拍或口报场记："S04-04，拼合归位，第一条"。
- 文件名：`S04-04_puzzle-snap_take01.mov`；失败的 take 不删，标 `_bad`。
- 场记表记录：镜号、take、时长、操作要点、是否可用。

1. 进入抉择屏，全景 2s：左侧隐痕、右侧金线、下方锔瓷、最下方隐藏结局「或许……有些伤痕不需要愈合？」。

**讲解要点**

#### S06-2 悬停预览与引导（04:38–04:58，20s）

**画面与操作**

1. 悬停「隐痕修复」2s：器身缝线变为浅灰、内嵌补釉带。
2. 悬停「金线表达」2s：器身缝线变为外凸金线 + 金铆点。
3. 点击「✦ 引导 · 依次预览三种修复」，自动轮播隐痕 → 金线 → 锔瓷，每段 2.6s；保留完整。
4. 点击「轻叩瓷身 · 先听一听」，播放破碎声；停留 1.5s。

**讲解要点**

- 悬停即预览，不提交选择；这是"先看再决定"的交互。
- 引导按顺序演一遍三种方式，降低理解成本；不是自动替用户选。
- 破碎声与修复后的声音不同，声音也是判断依据。

**旁白**

> 悬停卡片，器身会即时预演；"引导"会按顺序把三种方式各演一遍。

#### S06-3 工序台：清创（04:58–05:12，14s）

**画面与操作**

1. 点击「金线表达」→ 进入工序台；器身釉面暂时置灰。
2. 底部提示「断口还蒙着尘。逐个点去这三处浮尘（0/3）」。
3. 依次点击 3 个浮尘标记；每点一个，粒子散开、计数更新。
4. 有的标记在背面；按住器身拖动，把它转过来（保留 1 次旋转）。

**讲解要点**

- 工序与拼合同构：先清创，再落金/落胶，最后上釉。
- 浮尘标记落在真实模型表面，不是平面贴图。
- 背面标记需要手动转器身，和真实工序一样，不自动转。

**旁白**

> 选择之后不是直接出证书，而是一段和拼瓷同构的工序：先清创，点去断口上的浮尘。

#### S06-4 落金与上釉（05:12–05:28，16s）

**画面与操作**

1. 清创完成，自动进入第二步「沿裂缝落金（0/4）」。
2. 依次点击 4 个金点；每点一个，留下永久金点，计数更新。
3. 集齐 4 点，金线贯通，缝组显现；进入第三步「上釉」。
4. 按住「按住上釉 · 让釉色重新醒来」2s，充能条走满；釉色从灰里渐变回原色。
5. 自动进入证书。

**讲解要点**

- 落金 4 点是"金线的骨节"，不是随机装饰；点落在裂缝方位角上。
- 上釉是按住充能，不是单击；让"等待釉色醒来"成为体验。
- 釉色恢复同时作用于程序化器身与真实 GLB 材质。

**旁白**

> 再沿裂缝落胶或落金；最后按住上釉，让釉色从灰里醒来。

#### S06-5 锔瓷 B-roll（05:28–05:40，12s）

**画面与操作**

1. 从证书点「重新选择修复方式」→ 抉择屏 → 点「体验中国锔瓷 · 以钉接裂，以手惜物 →」。
2. 器身进入锔瓷模式；沿裂缝点击 4 次，放置 4 枚铜钉。
3. 每枚铜钉：两条钉脚 + 横梁，跨过裂痕；计数 1/4 → 4/4。
4. 四钉落定，提示「四枚锔钉落定，裂痕被轻轻接住」，1.5s 后进证书。

**讲解要点**

- 四钉是简化示意，不涉及真实钻孔、材料与工具。
- 这是"惜物修补"的数字表达，与金线的审美表达不同。

**旁白**

> 锔瓷要在裂缝两侧布下四枚铜钉，钉脚咬合，裂片重新连起来。

#### S06-6 现状保存 B-roll（05:40–05:48，8s）

## 5A. 补充功能演示（加长版 / 备查）

### A1 拼合辅助控件（约 20s）

**画面与操作**

1. 拼合屏 4/8，点击 ↶ 两次、↷ 一次，展示步进环绕（每次 15°/30°）。
2. 点击「⟲ 复位视角」，回到正面全景。

4. 点击「↺ 重新散落」，碎片回到散落位，进度归零；停留 2s，再点 2–3 片恢复。

**讲解要点**

**旁白**

### A2 2D 回退路径：提示位置与点击吸附（约 25s）

**画面与操作**

1. 用禁用 WebGL 的浏览器/启动参数进入拼合屏，显示二维碎片。
2. 点击「点击吸附 · 关」→「开」；先点一片碎片，再点它的归处。

**讲解要点**

- 2D 回退保证没有 WebGL 的设备也能完成全流程。
- 点击吸附与提示位置是这条路径的辅助；3D 主路径用点击即归位 + 青色对花投影替代。
- 两条路径共用同一套吸附判定与进度逻辑。

**旁白**

> 没有 WebGL 时，退回二维拼合：可以拖，也可以开启点击吸附；选中碎片后还能让提示位置闪一下。

> 录制提示：这是独立 B-roll，不要与 3D 主片混剪；画面风格差异要在字幕上标明「2D 回退路径」。

### A3 证书次级入口（约 30s）

**画面与操作**

**讲解要点**

**旁白**

### A4 讲解面板次级控件（约 30s）

**画面与操作**

### 7.2 转场语法

| 场景 | 用法 |
|---|---|
| 屏内动作 | 硬切；保留 0.2–0.3s 静止让观众看清 |
| 屏间切换 | 保留应用内 16 片碎瓷转场；不要二次加特效 |
| 章节切换 | 6–8 帧叠化，或在一个动作/声音点上硬切 |
| 器身匹配 | 委托页器身 → 拼合全息瓶 → 证书小像，沿器身中轴匹配剪辑 |
| 归位/扫描/金线 | 0.5× 慢放 8–12 帧；不要用光流补帧 |
| 四方式对比 | 2×2 分屏，细金线分隔，标签"隐痕/金线/锔瓷/现状保存" |
| 考察切换 | 场景淡入淡出 0.3s；机位/光照用硬切 |
| 结尾 | 成就卡 → 黑场 → 尾卡，留 1s 静音 |

### 7.3 节奏与音乐

- 前 2 分钟旁白密度高，音乐只做低频垫；拼合段让瓷鸣与粒子声成为节奏。
- 长卷段降音乐，留翻页声；抉择段回到低频，强调"停顿"。
- 证书段用一次柔和和弦；考察段用环境声（风/窑火/水）；展厅段用轻微底噪。
- 终局用一次完整和弦，尾卡收干净。不要用鼓点或强烈转场音效。

### 7.4 字幕与图形

- 章节标签：左下角，金色细线 + 章节名 + 英文小字；出现 3s 后淡出。
- 技术标注：右上角，等宽小字；只标 1 行，不堆参数。
- 关键数字：用金色，只标一次（9 屏、6 器、48 段、118 项测试）。
- 引号与术语：统一用「」；"数字示意""原创叙事""图测·待确认"保持原文。
- 不要把旁白逐字做成大段字幕；每屏最多 2 行，长句拆成 2–3 条。

### 7.5 调色与声音

- 调色：保留墨蓝夜色；暗部 +3，避免死黑；金色高光保护，不裁切；整体轻微降饱和 3%，让青花更稳。
- 去 banding：暗背景渐变容易起色带；加 1–2% 细噪点，或把码率提到 20 Mbps。
- 声音：系统声与旁白分开；旁白 -18 LUFS，系统声 -24 至 -20 LUFS；整体 -14 LUFS；真峰值 -1 dBTP。
- 齿音/呼吸：轻降 6–8kHz 齿音；保留自然呼吸，不要过度压缩。

### 7.6 导出

- 主片：H.264 High，1920×1080，30fps，16–20 Mbps，AAC 320 kbps，48kHz。
- 审片版：H.264，8 Mbps，便于微信/邮件传输。
- 字幕：独立 srt；同时提供硬字幕版，防止播放器不带字幕。
- 封面：1920×1080，首页全景 + 作品名 + 一句话定位；不要用拼图九宫格。

## 10. 评审问答预案

**Q1：作品的核心创新是什么？**
把"修复"从拼图小游戏变成一次有伦理选择的叙事体验：碎片来自真实模型本体切割，记忆与器物编年绑定，四种修复方式对应四种修复伦理，最后用证书与考察把体验落到文化记录上。技术上是"同源"：模型、碎片、纹样、证书小像共用一套轮廓与纹理数据。

**Q2：为什么是点击归位，而不是拖拽？**
3D 拖拽在受限空间里容易出现深度歧义与误吸附；点击归位把操作成本降到最低，把注意力留给"看纹样、认断口、做判断"。拖动仍然保留给 360° 观察；2D 回退路径保留拖拽 + 点击吸附两种方式。

**Q3：纹样是怎么来的？会不会是"贴图"？**
六件器物的纹样来自用户提供照片的柱面反投影，并与 GLB 的 UV 图集对齐；程序化纹样只作为照片未就绪/线上模式的兜底。碎片从 GLB 本体切割，断口是真实共享边，所以合拢时纹样能接上。我们不称其为"实物拓印"或"1:1 复原"，页面标注"数字示意"。

**Q4：AI 讲解会不会编造？**
默认走本地知识库：检索 + 领域判定 + 未知回答；每条答案带五层标签与来源，资料不足时统一回答"现有展览资料中没有足够依据"。远程大模型是可选适配层，默认关闭，前端不存密钥，不发送昵称/存档；讲解不写存档。角色"器灵 · 阿圆"明确标注为原创数字角色，不是历史人物复原。

**Q5：写实 3D 的"写实"依据是什么？**
三处景点按真实尺寸锚点与参考图建模，构件清单带来源编号与置信度（标准/官网原文/图测·待确认）；HUD 显示 fps/面数/draw calls/LOD/预算。能核对的给出处，不能核对的标不确定，这是"写实"的边界。

**Q6：为什么没有自由漫游/物理引擎？**
体验目标是"修复"而不是"逛场景"；自由漫游会带来眩晕、碰撞与性能问题。拼合台是受限轨道（偏航 360°、俯仰约 ±45.8°），碎片只在 XY 平面；考察场景用 OrbitControls + 预设机位，保证取景与性能可控。

**Q7：文化内容如何避免"编故事"？**
全站统一五层标签；器物原型来自故宫公开藏品资料并标注出处；委托人与器物经历为原创叙事；民间传说单独标注；传承资料摘记区分逐字引述与概括，并标来源/登记日期；线上公开版停用馆藏照片，只保留文字出处。

**Q8：完成度如何证明？**

### 11.1 录制风险

### 11.2 已知功能边界（重要，避免误读）

1. **「提示位置」在 3D 主路径下不可用。** 3D 拼合是"点击即归位"，选中态在 pointerup 后立即清空；`#locate` 需要 `selected`，点击会提示"先选中一片瓷"。工具行的 ◎（`#hint`）同样依赖 `selected`，在 3D 下也会落空。这两者是 2D 回退路径的辅助功能。主片不演示，改用青色对花投影 + 整幅纹样参考。后续修复建议：3D 下长按选中，或点击后保留 selected 1.5s。
2. **全息终章默认带暖金透光。** 它在"全部归位"时触发，早于修复方式选择。主片旁白只说"全息壳体退场、成品回落"，不强调金色；本片最终选择"金线表达"，保持视觉一致。若最终选择隐痕，终章与长卷之间加 0.2s 叠化，避免误读。
3. **「点击吸附」在 3D 下隐藏。** 它是 2D 回退路径的替代操作；主片不展示，避免让评审误以为主路径依赖它。
4. **分享二维码是程序化占位。** 正式域名确定后替换 `public/share-qr.png`；片中要标注。
5. **模型缺失会静默回退程序化器身。** 这是容错设计，不是主路径；不要录回退画面，除非在 S10 说明"失败不阻塞流程"。
6. **localStorage 清除会重置进度。** 设计如此；录制前备份三个槽的 JSON。
7. **iOS 陀螺仪需要授权。** 手机端「启用倾斜视线」可能弹权限；录屏时先允许。

### 11.3 应急重录清单

- 每条镜头单独成文件；失败 take 标 `_bad`，不覆盖。
- 优先保 S04、S06、S07、S08、S09；时间不够时砍 S02/S10 的细节。
- 如果拼合 take 出现误点，不要重录整段；补录一个"归位特写"覆盖，剪辑用跳切。
- 如果考察场景加载失败，先回证书再进；仍失败则重启浏览器，不要在现场排障。
- 所有截图与录屏使用同一浏览器、同一缩放、同一存档状态；换机器会破坏一致性。
