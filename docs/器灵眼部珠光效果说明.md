# 器灵 · 阿圆：眼部动态珠光说明

> 版本：2026-10-19（第二轮：放大与流动感） ｜ 对应实现：`src/modules/qiling-eye-pearl.js`、`src/modules/guide-character3d.js`
> 目标：让器灵的眼神从"死黑两块"变成有湿润感、有呼吸、有回应的珠光，同时不改变模型本身、不引入外部素材。
>
> 本轮的改动：**修正了眼睛坐标**（原先的高光被眉骨挡住）、放大珠光覆盖面积、提高高光强度、新增「流光带」层，并关闭精灵的深度测试以消除转头时高光断裂。

## 1. 为什么用叠加层，而不是改模型

`public/models/qiling.glb` 是一整块网格（约 12.9 万顶点，单一 `MeshPhysicalMaterial`），**眼睛画在贴图里，没有独立的眼球/瞳孔/高光节点**。因此：

- 不重绘贴图：会破坏模型原有的青花、开片与金缮纹理；
- 不新增眼球几何：会与原有眼型、金边发生穿插；
- 采用 **Sprite 叠加层**：在双眼表面叠程序化高光，随 `root` 转头、悬浮一起动，不改变模型资产。

## 2. 位置（本轮已修正）

坐标来自对 `qiling.glb` 在 `fitToHeight(root, 2.05)` 后的**渲染图暗区质心 + 射线拾取**（参考画布 600×810、FOV 34°、相机 `(0, 1.05, 4.8)`、看向 `(0, 0.42, 0)`）。

| 眼睛 | 模型局部坐标（x, y, z） | 表面法线 | 说明 |
|---|---|---|---|
| 左眼（观众视角左） | `(-0.1793, 0.5672, 0.1754)` | `(-0.313, 0.114, 0.943)` | 瞳孔中心 |
| 右眼（观众视角右） | `(0.0897, 0.5798, 0.1805)` | `(0.196, 0.150, 0.969)` | 瞳孔中心 |

- 珠光层沿**表面法线**前移 `0.018`（`EYE_PEARL_LAYOUT.forward`），不再沿 `+z` 前移。
  上一版按 `+z` 前移 0.015，但拾取点其实落在瞳孔上方靠近眉骨的位置，高光被脸挡住，肉眼几乎看不见——这是"高光不明显"的真正原因。
- 眼球实测约 **0.30（宽）× 0.22（高）** 世界单位；下面所有尺寸都按这个尺度配比，保证不糊出眼眶。
- Sprite 挂在 `root` 下，器灵转头 ±0.26 rad、上下悬浮时珠光跟着眼睛走。

## 3. 五层珠光

| 层 | 位置 | 尺寸（世界单位） | 颜色 | 作用 |
|---|---|---|---|---|
| `sheen` 珠光底 | 瞳孔中心上移 0.012 | 高 0.190 × 宽 0.277（aspect 1.46） | 淡青 `#96C6FF` → 淡紫 `#CDB9FF` → 暖珍珠 `#FFE2B0` → 白 | 让眼内有一层釉光，瞳孔不是纯黑 |
| `pearl` 主珠光 | 瞳孔偏上 +0.032 | 高 0.182 × 宽 0.211（aspect 1.16） | 白 `#FFF8E8` ↔ 淡青 `#DCEFFF` ↔ 暖金 `#F2D6A2` | 主 catchlight，负责"眼神" |
| `flow` 流光带 | 瞳孔中心 +0.012，横向左右扫 | 高 0.082 × 宽 0.279（aspect 3.40） | 冷白偏青 | 一道细长水光缓缓掠过，制造眼波流动 |
| `glint` 小高光 | 主珠光右上 (+0.034, +0.004) | 0.058 | 暖白 `#FFF8E6`（带一点金） | 窄脉冲闪烁，制造"活"的瞬间 |
| `warm` 暖金卫星 | 眼底左下 (-0.016, -0.032) | 0.028 | 暖金 `#FFD9A0` | 第二色温，呼应描金/金缮 |

设计取向：

- **蓝白为主、暖金为辅**。蓝白对应青花与釉面，暖金对应器灵身上的金缮裂纹；不引入新色系。
- 全部 **AdditiveBlending + `toneMapped: false`**，只加光、不盖住原有眼型与金边。
- 主珠光偏上而非居中：动画角色的 catchlight 通常在瞳孔上方，正中心会像"塑料眼"。
- 珠光底比主珠光大，但**宽度（0.277）小于眼球宽度（0.30）**；单元测试锁住这条，避免下次调大时糊出眼眶。

## 4. 动效与节奏

### 4.1 待机

| 动效 | 周期 / 速度 | 幅度 | 观感 |
|---|---|---|---|
| `sheen` 旋转 | 0.30 rad/s（约 21s 一圈） | 连续 | 眼内虹彩缓慢流动，像釉光在转 |
| `sheen` 呼吸 | 0.9 rad/s（约 7s） | 缩放 ±3.5% | 极轻的湿润感 |
| `pearl` 漂移 | x 0.55 rad/s、y 0.43 rad/s（约 11–15s） | ±0.009 / ±0.007 局部单位（约 2–4px） | 高光在眼内"游"一小段 |
| `pearl` 呼吸 | 0.82 rad/s（约 7.7s） | 缩放 ±7% | 眼神有轻微起伏 |
| `flow` 横扫 | 0.22 rad/s（约 29s 一个来回） | 横向 ±0.086，纵向 ±0.010 | 水光掠过瞳孔，是"流动感"的主要来源 |
| `glint` 闪烁 | 0.85 rad/s（约 7.4s 一个窄峰） | 透明度 +0.40，缩放 +34% | 约 7 秒轻闪一次，像眨眼后的反光 |
| `warm` 呼吸 | 0.6 rad/s（约 10.5s） | 透明度 ±0.04 | 暖金在眼底慢慢明灭 |

左右眼 `phase` 分别为 `0` 与 `1.73`，所有周期都错开，避免两只眼"同步闪"的机械感。

### 4.2 说话

`setSpeaking(true)` 后，0.35s 平滑过渡到：

| 项 | 待机 | 说话 |
|---|---|---|
| `sheen` 透明度 | 0.54 | +0.16 |
| `pearl` 透明度 | 0.64 | +0.14 |
| `flow` 透明度 | 0.30 | +0.12 |
| `glint` 透明度 | 0.56 | +0.20 |
| 漂移/闪烁速度 | ×1.0 | ×1.25 |
| `warm` 透明度 | 0.22 | +0.12 |

说话时只是"更亮、稍快"，不做夸张放大；器灵在讲解时本身有上下律动，眼部再大幅动会抢字幕。

### 4.3 强度边界（防"过度反光"）

- 单层透明度上限 < 0.9；主珠光 0.64，即使说话峰值也只到 0.80。
- 闪烁是**窄脉冲**（`sin^10`），只在峰值附近 0.3–0.5s 可见，不是持续频闪。
- 珠光底上移 0.012、主珠光上移 0.032：瞳孔下缘始终留一条暗边，不会整颗眼变成"白球"。
- 所有位移都在 0.01 局部单位量级；在 178×240 的器灵画布里约 2–4px，属于"感觉到在动、但说不清哪里动"的幅度。

## 5. 为什么关闭深度测试

眼球是凸面，平面 Sprite 只有中心能贴在表面外侧，边缘会被眼面本身遮掉；叠上 `root.rotation.y ±0.26` 的转头，高光会一块块消失，看起来像"闪一下就没了"。

处理方式：`depthTest: false` + 所有纹理 alpha 到边归零 + 整层尺寸收在瞳孔轮廓内。
代价是珠光永远画在模型之上，因此**尺寸必须小于眼型**——这条已由单元测试（`sheenWidth < 0.30`）兜住。

## 6. 状态与降级

| 状态 | 行为 |
|---|---|
| 正常（默认） | 五层全开，按 4.1/4.2 动 |
| 说话 `setSpeaking(true)` | 亮度 +、速度 ×1.25，0.35s 过渡 |
| 低画质 `low` | 只保留 `sheen + pearl`（每眼 2 个 Sprite），**静态**呈现，纹理 64px |
| 减少动态 `reduced` | 五层保留，但**不旋转/不漂移/不闪烁**；`setSpeaking` 只补一帧静态亮度 |
| 3D 加载失败 | 回退 2D 水墨剪影，珠光不参与，不报错 |
| WebGL 上下文丢失 | 按原逻辑回退 2D，珠光随 3D 场景一起销毁 |
| `dispose` | 移除 Sprite、释放材质与 5 张 CanvasTexture，不残留 |

低画质/减少动态遵循 `guide-character3d.js` 顶部约束："减少动态 / 低性能模式不播动画只做静态呈现"。

## 7. 性能

- 正常：每眼 5 个 Sprite，共 10 个；4 张 128px / 2 张 64px CanvasTexture（按材质复用）；每帧只改 opacity/scale/position/rotation，无几何重建。
- 低画质：每眼 2 个 Sprite，共 4 个；64px 纹理；不跑时间驱动更新。
- 渲染仍受 `visible` 门控：器灵不可见时 `rAF` 停止，不产生额外开销。
- 无外部图片、无网络请求。

## 8. 调参入口

所有参数集中在 `src/modules/qiling-eye-pearl.js` 的 `EYE_PEARL_LAYOUT`：

```js
EYE_PEARL_LAYOUT = {
  eyes: [ { id, position, normal, phase, tilt }, ... ],
  forward,
  sheen: { worldSize, aspect, opacity, speed },
  pearl: { worldSize, aspect, opacity, driftX, driftY },
  flow:  { worldSize, aspect, opacity, sweep, speed },
  glint: { worldSize, opacity, offset },
  warm:  { worldSize, opacity, offset },
  colors: { blue, white, gold, warm }
}
```

- `worldSize` 是**高度（短边）**，`aspect` 是**宽 / 高**；改宽度改 `aspect`，别只拉 `worldSize`。
- 想让"更亮"：先加 `pearl.opacity`（0.64 → 0.70），不要先加 `worldSize`；宽度上限是 0.30。
- 想让"更灵"：加 `flow.opacity`（0.30 → 0.36）或 `flow.sweep`（0.086 → 0.098）；`glint` 峰值已经很窄，再加会像故障灯。
- 想让"更稳"：降 `sheen.opacity`，或把 `sheen.speed` 从 0.30 降到 0.24；不要加快 `pearl` 漂移。

## 9. 换模型后如何重算坐标

1. 用参考画布（600×810、FOV 34°、`(0,1.05,4.8)` 看向 `(0,0.42,0)`）渲染正面图；
2. 把渲染结果画到 2D canvas，取 `alpha > 200` 且 `r<70 / g<78 / b<95` 的连通块（排除透明背景），最大两块即左右眼；
3. 用两块质心的屏幕坐标 + `THREE.Raycaster` 取第一个命中点；
4. `root.worldToLocal(hit.point)` 得局部坐标，`face.normal` 转局部得法线，替换 `EYE_PEARL_LAYOUT.eyes[]`；
5. 跑 `node --test tests/qiling-eye-pearl.test.js`，确认坐标在包围盒内、法线接近单位长度。

## 11. 边界

- 珠光只加在**眼睛表面**，不改变眼型、金边、开片与青花纹样。
- 不使用外部贴图/模型/字体；纹理全部 Canvas 程序化生成。
- 不写入任何存档，不参与讲解知识库与流程状态。
- 器灵仍是"原创数字角色"，眼部效果不改变这一口径。
